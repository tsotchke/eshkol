# LeakSanitizer suppression file for the linux-x64-asan-ubsan CI lane, the
# standalone LeakSanitizer profile and tests/memory/leak_audit_gate.sh
# (ADR-0010 gap A12).
#
# Policy: this file names only retentions inside third-party libraries that
# this repository does not build or own. Every Eshkol allocation is either
# released or held by a rooted owner, so a LeakSanitizer report that points
# into this repository is a defect to fix, never a rule to add here.
#
# Each rule matches one call path in one third-party component -- never a
# blanket "leak:*", a whole library, or a size -- and carries a comment that
# says what it matches and why the retention belongs to that component.
# scripts/check_leak_detection_selftest.sh proves this file still lets a real
# leak through by leaking on purpose under exactly these rules.
#
# Format: https://clang.llvm.org/docs/AddressSanitizer.html#suppressing-memory-leaks
#   leak:<function-or-module-substring>
#
# Loaded via LSAN_OPTIONS=suppressions=<this file> (see .github/workflows/ci.yml).
#
# ---------------------------------------------------------------------------
# Third party: LLVM ORC JIT
# ---------------------------------------------------------------------------
# llvm::orc::DynamicLibrarySearchGenerator opens the host process (or a named
# shared library) through llvm::sys::DynamicLibrary, whose handle registry is
# process-global and deliberately never closed: LLVM keeps loaded libraries
# resident for the life of the process so that resolved symbol addresses stay
# valid. The generator and that registry are LLVM's, not this project's, and
# the JIT's lifetime ends with the process. Scoped to the generator class.
leak:llvm::orc::DynamicLibrarySearchGenerator
#
# ---------------------------------------------------------------------------
# Retired rules
# ---------------------------------------------------------------------------
# Earlier revisions of this file also named Eshkol allocation sites. Each was
# replaced by an owner or a release, and LeakSanitizer now checks them:
#   parse_list, parse_atom, parse_function_signature, expandNode,
#   transformInternalDefinesToLetrec, parse_quoted_data_with_token,
#   parse_quoted_list_internal, parse_expression
#       AST node storage comes from the rooted AST node owner
#       (inc/eshkol/frontend/ast_nodes.h), released with the string owner at
#       driver teardown.
#   add_local
#       Bytecode-compiler local names are owned by their slot in the chunk's
#       locals array and released on slot reuse or chunk free
#       (lib/backend/vm_parser.c).
#   eshkol_push_exception_handler
#       A thread's cached handler frames are released when the thread ends
#       (lib/core/runtime_exceptions_hosted.cpp).
#   eshkol_lazy_future_create_ptr
#       Matched no report in the sanitizer lane's workloads; LeakSanitizer
#       checks it like any other runtime allocation.
#
# In the Linux runs that retired those rules, the LLVM ORC rule above matched
# no report either. It stays because the retention it names is LLVM's, and a
# JIT route that loads a host library through the generator will reach it.
