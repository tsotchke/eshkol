Closes ledger **LE-12** (`.icc/silent-wrong-ledger.yaml`, LOUD-ERROR/structural) and promotes **op:CURL** and **op:DIVERGENCE** in `tests/vm_parity/PARITY.tsv` from `gap` to `vm-supported`.

LE-12 booked two separable defects. Both are fixed here, and fixing them exposed two more in the same operator that no gate could have caught.

## 1. The crash — a documented shape that was fatal

```scheme
(define (F v) (list (vector-ref v 0) (vector-ref v 1) (vector-ref v 2)))
(display (curl F (vector 1.0 2.0 3.0)))
;; [Eshkol] fatal signal: SIGSEGV (segmentation fault) at address 0x2002
```

`curl` and `divergence` both delegate to `AutodiffCodegen::jacobian`, whose **output**-shape dispatch is a two-way split: *is the heap subtype `VECTOR`? if not, read it as an `eshkol_tensor_t`*. A `(list …)` return is a `HEAP_SUBTYPE_CONS` cell — which **is** a `HEAP_PTR`, so it passed the type check, missed the vector arm, and fell into the tensor arm, where the cons cell's `car`/`cdr` words were loaded as the tensor's `dims` and `elements` **pointers**. Both of the operator's output sites had the defect: the test call that determines the output dimension `m`, and the per-row AD call.

This is the mirror image of ESH-0360/#343, which added the cons arm to the **point** side and never touched the output side — the same "fixed at the symptom's location, not the bug class" shape the ledger records elsewhere.

The shape was documented all along: `docs/reference/ad/architecture.md` states that `divergence` and `curl` "accept a field that returns a **list or a vector**".

### The trap in the obvious fix

The natural fix is to reuse the existing `eshkol_list_to_svec`. That would have been **worse than the crash**. It exists for the AD *point* and deliberately forces every element to `ESHKOL_VALUE_DOUBLE`; under AD mode each output component is an AD node, `eshkol_ad_seed_to_double` would refuse it, and the component would be replaced by a fabricated `0.0`. Every partial derivative would read zero and `(curl F pt)` would return `#(0 0 0)` for **every** field — which is the correct answer for a gradient field, and gradient fields are what every worked example in the doc set uses. The bug would have passed the most likely test.

So this adds `eshkol_list_to_svec_raw`, which copies each `car` verbatim, tag and all. The test file's section 5 exists specifically to catch that failure mode: a field whose curl is `(4, 6, 2)` — three distinct nonzero numbers, so an all-zeros result, a permutation, or a sign flip all fail.

## 2. The arity convention — the engines disagreed about which programs exist

Native passed the point whole, always; the VM spread it into N, always. So:

- a 3-parameter field failed on native at the **LLVM verifier** — "Incorrect number of arguments passed to called function", an unbuildable module rather than a wrong answer;
- the **documented** arity-1 field could not be called on the VM at all — `vm_call_closure_from_native` sets `fp = sp - 3` unconditionally, so `v` bound to the first spread scalar and `vref` on it failed.

The docs are unambiguous: `docs/reference/ad/operators.md:30` — "`f` is a one-argument function" — and every worked example in all twelve documenting files writes `(lambda (v) … (vref v i) …)`.

Both engines now resolve the field's arity by the **same rule `gradient` already used on both sides** (PARITY.tsv op:GRADIENT, *"arity-resolved"*): arity 1 takes the whole point, arity N takes N spread scalars. The documented form is the unchanged native default and is newly callable on the VM; the VM's spread form is unchanged and is newly callable on native. Applied to `divergence` too, and the VM's inline dual-vector construction was factored into `vm_ad_make_dual_vector` so the family shares one rule instead of writing it four times.

Known limitation, recorded at the call site rather than silently narrowed: through a **runtime closure** (a field arriving as a callable parameter) `jacobian`/`divergence`/`curl` implement the arity-1 convention only, because the closure's arity is a runtime value and spreading it needs the compile-time arity switch the gradient path has. The documented shape works there; the spread shape does not.

## 3. An out-of-bounds read, found while fixing (2)

`curl` admits `n >= 2` — and `docs/API_REFERENCE.md` advertises "Works for n>=2 (differential 2-forms)" — but then named row/column `2` unconditionally. On a 2-D field the Jacobian is 2×2, so `J[2,1]` and `J[2,0]` read a full row past the elements array. A **wrong answer**, not a crash, so nothing was ever going to report it. Indices outside the Jacobian's own dims now yield an exact `0.0`, which is also the mathematically correct value: a 2-D field embedded in 3-space has `F₃ = 0` and no `z` dependence.

## 4. A silent `()` on the VM, found while taking the cross-engine baseline

VM `curl` carried its own inline point extraction recognizing only `VAL_PAIR` and `VAL_TENSOR`. A genuine `VAL_VECTOR` point — what **both** `(vector 1.0 2.0 3.0)` and the reader literal `#(1.0 2.0 3.0)` evaluate to, since `vm_compiler`'s `vector` form emits `OP_VEC_CREATE` and deliberately does not make a tensor — matched neither branch, left `n` at 0, and fell into the `n != 3` arm to push a silent `()`. Both forms are documented accepted points and both already appear in the test corpus; the operator answered `()` for them with no diagnostic. Now uses `vm_ad_extract_point`, the shared helper every sibling already used.

## Doc changes

- `README.md`, `docs/FEATURE_MATRIX.md` — both still said the VM's `divergence`/`curl` were `h=1e-7` central differences. That stopped being true on 2026-08-26; the rows now describe what the code does, and cite the corpus rather than asserting agreement.
- `docs/reference/ad/operators.md` — the field-arity and field-return rules are now an explicit table. They were the contract this work had to implement and were previously only inferable from examples. The `curl` entry gains a **non-vanishing** example in all four accepted spellings, because every worked example in the doc set was a field whose curl is zero.
- `docs/tutorials/01_AUTODIFF_AND_ML.md` — carried `(divergence field-x field-y field-z 1.0 2.0 3.0)`, a six-argument form with three separate scalar fields that contradicts every other doc and the two-field AST node, and could never have run. Replaced with the real two-argument form.

## Not in scope

- op:JACOBIAN stays `gap`. Its VM side has an independent, separately tracked defect ("returns tensor handle, wrong values") that arity resolution does not address.
- A field returning a `(tensor …)` remains native-only on both `curl` and `divergence`: the VM raises a named diagnostic because `VmTensor` holds bare doubles and drops every tangent at construction. Named explicitly in both PARITY.tsv justifications rather than left implied (`.icc/ad-carrier-manifest.yaml` `fork_debt.blocked_on`).
