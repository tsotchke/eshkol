# `eshkol/strict_resource_contracts.h`

Typestate contracts for every native handle family checked by `eshkol-run --strict-resources`. One table describes how each handle-producing, handle-consuming, and handle-observing operation moves a handle through the typestate `open -> borrowed -> open ... -> closed` (docs/design/adr/0056-linear-handle-typestate.md). The ownership checker in exe/eshkol-run.cpp reads only this table: no operation name is special-cased elsewhere. Module contracts are trusted only for the exact stock SDK source they were reviewed against. Each entry pins the SHA-256 of that source file, and the export set must equal the contract names. An edited module keeps compiling in the default profile but is refused by the strict profile until its contract is reviewed and re-pinned (scripts/strict_resource_pins.py). Builtin contracts apply only when the name is not lexically rebound.
