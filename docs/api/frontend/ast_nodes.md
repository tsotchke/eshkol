# `eshkol/frontend/ast_nodes.h`

The one owner of AST node storage. The parser and the macro expander build `eshkol_ast_t` nodes and the side structures hung off them: child and argument arrays, parameter and binding name arrays, HoTT type-annotation arrays, patterns, match clauses, macro definitions and tensor-literal dimension arrays. All of them are allocated here and nowhere else, through eshkol_ast_new() and eshkol_ast_new_array(). ## Ownership model The owner is a process-rooted, append-only, chunked arena, the sibling of the AST string owner (ADR-0021, ast_strings.h) and built on the same arena. It follows the same lifetime rule: frontend data is valid for the whole compilation that produced it, because a node built during parsing is read by macro expansion, module renaming, type checking and codegen long after the parse unit is gone. - **Nobody frees an individual node or array.** Rewriting a subtree stores new pointers and leaves the old storage to the owner. The types placed here are trivially destructible, so dropping them runs no code. - **Reachability.** Every chunk is linked from a process-global root, so LeakSanitizer sees the storage as live for as long as the compilation lives; it is rooted, not suppressed. - **Teardown.** eshkol_ast_nodes_teardown() releases every chunk at once. It is called at the same points as eshkol_ast_strings_teardown(): when the batch driver's main() returns, in the REPL's ordered exit, and after each parser-fuzzer input. Embedders that parse repeatedly in one process keep the process-lifetime default. Retention is proportional to source read plus the nodes expansion synthesizes, the same growth law as the NodeId table and the string owner. ## Sanitizer precision Under AddressSanitizer each allocation is followed by a poisoned redzone, so indexing past the end of a child array is still reported. After teardown a stale node pointer is a heap-use-after-free. ## Thread-safety Allocation takes a mutex. Teardown must not race with allocation.

### `eshkol_ast_nodes_teardown`

*Function* — line 108

```c
void eshkol_ast_nodes_teardown(void);
```

Release all AST node storage at once. Every pointer the owner handed out becomes invalid. Call only when no AST produced in this process will be read again. The owner stays usable. When the environment variable `ESHKOL_AST_NODES_STATS` is set (to anything but `0`/`false`), teardown first writes one line to stderr: `eshkol-ast-nodes: allocations=N requested=N chunks=N reserved=N`.
