# `eshkol/frontend/effect_syntax_core.h`

The one lowering of the algebraic-effect forms (ADR-0045). `define-effect`, `handle`, `handle-shallow` and `declare-effects` are rewritten here, over the neutral syntax tree of syntax_rules_core.h, into ordinary Scheme that calls the effect runtime (lib/core/control/effects.esk). Both engines run this same source: the native parser converts its reader syntax (SyntaxDatum) to `eshkol_syn` and back, and the bytecode VM converts its reader nodes. Neither engine has its own copy of the rules. (define-effect Name (op formals...) ...) => (begin (define Name (%effect-make 'Name)) (define op (%effect-operation Name 'op '(formals...))) ...) (handle body clause...) deep handler (handle-shallow body clause...) shallow handler clause ::= (return (x) e...) applied to a normal result | ((op formals...) k e...) k is the resumption | (fun (op formals...) e...) resumes with the value of e... => (%effect-handle 'light|'full 'deep|'shallow <return> (list (%effect-clause op '<kind> (lambda ...)) ...) (lambda () body)) (declare-effects name (Label ...)) => (%effect-declare 'name '(Label ...)) Every operation clause is classified by how its body uses the resumption k. The classification selects the cheapest runtime strategy that has the same meaning: abort k never occurs: the handled computation is abandoned and the clause's value is the value of the `handle` form. No continuation is captured at the operation. tail every tail position of the body is `(k e)` and k occurs nowhere else: the clause always resumes, as its last act. It runs in place at the operation, and `(k e)` becomes `e`. No continuation is captured. (A `fun` clause is this kind.) general-tail k occurs only as the operator of a call in tail position, but some path does not resume: the continuation of the operation is captured; resuming does not capture the resumption site, because nothing in the clause follows it. general anything else (k stored, passed, called more than once in sequence, or called in non-tail position): the resumption site is captured too, so `(k v)` returns the result of the resumed computation. A handler is `light` when every clause is `tail`: it captures nothing. The form is recognised only when it is shaped like one: a `handle` whose trailing operands are not all clause-shaped is left as an ordinary call, so a program's own procedure named `handle` keeps working. The lowering emits only symbols and lists (never a new atom), because each engine rebuilds atoms from the reader token that produced them. Header-only and C/C++ compatible; every function is static inline.
