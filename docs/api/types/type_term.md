# `eshkol/types/type_term.h`

Interned core terms of the dependent type language (ADR-0042). One term language serves every type-level judgment the checker makes about dependent types: Pi and Sigma telescopes, universes, type-family applications such as the length-indexed vector `(vector real n)`, and the index terms those families are indexed by (integer literals, program variables, arithmetic, and uninterpreted stable projections such as `(car p)` and `(vector-length v)`). Terms are hash-consed: two structurally equal terms are the same TermRef. Binders use de Bruijn indices, so alpha-equivalent terms are also the same TermRef; binder names are kept only as printing hints. Definitional equality is therefore "normalize, then compare references": - delta: a stable program variable whose value is an index term unfolds to that value (`(let ((n 3)) ...)` makes `n` and `3` definitionally equal); - beta for type families happens when a family application is resolved (the checker instantiates a define-type body with its arguments), so a term never contains an unexpanded user family; - index arithmetic is put in polynomial normal form over the integers (sum of monomials with integer coefficients, monomials ordered), which decides equality of polynomial index expressions exactly. Metavariables stand for indices a call site has not supplied (the implicit binders of a dependent signature). unify() solves them first-order and solves a linear equation in a single metavariable (`?n + 1 = 4`). The store is owned by TypeEnvironment; the checker reaches terms through TypeEnvironment::termOf() and TypeEnvironment::typeFromTerm(). Extensions (identity types, refinement predicates, effect rows) add a TermKind and its cases here rather than a second term language.
