# `eshkol/types/quantum_types.h`

Quantum register types for the HoTT checker (ADR-0048). The quantum specialisation of ADR-0004 on the checker that exists today: - `qreg<e>` a register of e qubits. Linear (TYPE_FLAG_LINEAR): it is used exactly once, so the no-cloning and no-discard rules of the linear `Qubit` type apply to whole registers unchanged. - `qidx<e>` the address of one qubit of a `qreg<e>`: a natural number below e. Two `qidx` arguments of one application must name different qubits (a gate on qubit i "twice" would copy it). - `qregion` the capability of one quantum region. `qalloc` needs it, so allocation is lexically scoped to the region that owns the simulator state; a region body may not return quantum data. - `qregion-body` the parameter type of `call-with-quantum-region`: a procedure of one `qregion` whose result is classical. Indices are linear expressions over naturals, `c + a1*v1 + ... + ak*vk` (IndexExpr). Variables are bound by unification at applications, or, when a variable is spelled like a parameter of integer type, by the compile-time value of that argument (`(qalloc qr 3) : qreg<3>`). An index the checker cannot know (a run-time size) is the bare family `qreg`, which is still linear and is compatible with every dimension: dimension checking is gradual, linearity is not. Every finding is reported through the checker's linear-violation channel, so it is fatal in every mode but `--unsafe`, on the native and the bytecode engines alike (the VM runs the same checker through linear_check_bridge).
