# `eshkol/types/hole_synthesis.h`

Type-directed completion of `??` synthesis holes (ADR-0052). A program may leave `??` where an expression belongs: (define (area (w : integer) (h : integer)) : integer ??) The type checker reports each hole with the type its position expects and with its scope still live (HoleObserver). HoleSynthesizer then enumerates terms bottom-up by size from the bindings in scope at the hole and a typed table of builtin operators, composing only arguments of the parameter types each operator declares; ranks the candidates of the expected type by how many distinct local bindings they use, then by size; and keeps those that the checker itself accepts at the expected type (TypeChecker::checkSpeculative, the checking direction Γ ⊢ e ⇐ τ). fill() replaces each hole with its best candidate and prints the candidates as a diagnostic; a hole with no well-typed completion within the size bound is an error.
