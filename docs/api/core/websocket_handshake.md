### `eshkol_ws_mask_payload`

*Function* — line 441

```c
static inline void eshkol_ws_mask_payload(unsigned char* bytes, size_t length,
 size_t payload_offset,
 const unsigned char mask[4]) { ... }
```

Masks `length` bytes of a client frame payload in place. RFC 6455 section 5.3: every frame a client sends is masked with that frame's key, byte i of the payload against key byte `i % 4`. A sender that copies the payload out in chunks must keep counting from the payload's start, not from the chunk's: restarting the count at each chunk would mask correctly only when the chunk length happens to be a multiple of four, and silently corrupt every frame larger than one chunk otherwise. `payload_offset` is the index, within the whole payload, of the first byte in `bytes`, which is what makes the chunked caller correct.

**Parameters**

- `bytes` — Buffer to mask in place.
- `length` — Bytes in `bytes`.
- `payload_offset` — Offset of `bytes[0]` within the whole payload.
- `mask` — The frame's 4-byte masking key.

### `eshkol_ws_max_frame_bytes`

*Function* — line 497

```c
static inline size_t eshkol_ws_max_frame_bytes(void) { ... }
```

The largest frame payload this client will accept, in bytes. A budget, not a constant: `ESHKOL_WS_MAX_FRAME_BYTES` overrides it, the way the server's three budgets are overridden. The default is 64 KiB. A frame declaring more is refused with close code 1009 (message too big) and the connection is closed, because a client that returned without consuming the payload would leave the stream desynchronised: every later read would parse attacker-chosen payload bytes as a frame header.

### `eshkol_ws_valid_utf8`

True when `length` bytes at `text` are well-formed UTF-8. RFC 6455 section 8.1 requires a client to fail the connection on a text frame whose payload is not valid UTF-8.
