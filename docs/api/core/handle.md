# `eshkol/core/handle.h`

Generation-tagged ownership handles for native resources. The registry is synchronized and stays outside movable arena storage. Borrowing is exclusive (OPEN -> BORROWED -> OPEN). Close while borrowed returns EBUSY. Close marks CLOSING under the lock, invokes the callback without the lock, and becomes terminal CLOSED even if the callback fails; uncertain OS closes must never be retried. Destroy rejects borrowed or closing entries, otherwise closes each remaining open entry once outside the lock. A create call transfers sole native-resource ownership only when it returns OK; on any failure, ownership stays with the caller. IDs and borrow leases are registry-local. Destroy returns ECLOSE if any callback fails but still completes cleanup and frees the registry. The owner must synchronize registry lifetime against external operations; close callbacks may re-enter while destruction is in progress. Failure outputs are left untouched. A successful state query may report CLOSED until its slot is reused; expired IDs after reuse are invalid. Lease values are never recycled; exhaustion makes future borrows fail. Slots at the maximum generation are retired instead of wrapping to an old ID. Interruption and close-after-release let one thread end another thread's wait without invalidating its borrow: interrupt marks the identity and wakes the borrower's registered waker; close-after-release additionally makes the identity unusable at once and runs the close callback exactly once when the active borrower releases. Exact registries keep every identity at or below 2^53 - 1 so it survives binary64 numeric boundaries unchanged.
